# Daily Budget Flow (Spend Tracker): project context

Context for future coding sessions. Read this before changing anything.

## What the app is

A local-first, mobile-first personal spending tracker. It has two separate budgets:
**weekday** (Mon–Fri) and **weekend** (Sat–Sun). The app answers one question:
*am I ahead or behind plan this month?* There is no backend and no auth. All data lives on the device
(SQLite key-value store). It is a native Expo (React Native) app; Android first, iOS later from the same code.
The currency is hard-coded to ₹ with `en-IN` number formatting.

## Constraints you must respect

- Native app: **Expo SDK 58 / React Native 0.88**, Android first. iOS builds later from the same
  code (EAS Build or a Mac). There is no web product; the web export exists only for previews.
- Expo changes every SDK. Check the installed package's `.d.ts` files (or docs.expo.dev, which
  may be blocked in sandboxes) instead of relying on memory.
- Add native libraries with versions from `node_modules/expo/bundledNativeModules.json`
  (`npx expo install` needs network access to api.expo.dev).
- `android/` and `ios/` are generated by `expo prebuild` (Continuous Native Generation) and are
  gitignored. Configure native behaviour in `app.json` or config plugins, never by hand.
- Don't rewrite pushed history (no force-push or amending pushed commits).
- Previously built with Lovable and then Capacitor; both are fully removed. Don't reintroduce them.

## Stack

Expo Router (file routes in `src/app`) · native tabs (`expo-router/native-tabs`: UITabBar on
iOS, Material bottom navigation on Android) · native form sheets (`presentation: "formSheet"`)
· StyleSheet + theme tokens (no CSS) · `expo-sqlite/kv-store` storage · `expo-symbols` (SF
Symbols / Material Symbols) · `react-native-svg` charts · `@react-native-community/datetimepicker`
· `expo-haptics` · `expo-document-picker` + `expo-file-system` + `expo-sharing` for backups ·
Cormorant Garamond (brand display font) · date-fns.

Commands: `npm start` (dev server; needs a dev build or Expo Go on a phone), `npm run android`
(local build, needs the Android SDK), `npm run typecheck`, `npm test`, `npm run format`,
`npm run preview:web` (static web export for screenshots only).
`npm test` runs `src/**/*.test.ts` with Node's built-in runner (`--experimental-strip-types`).
Test files and the modules they import use explicit `.ts` relative imports and only
`import type` from `@/` paths.

CI (`.github/workflows/ci.yaml`, manual `workflow_dispatch`): every mode runs typecheck, tests
and a Metro bundle. `debug`/`release` then run `expo prebuild` and Gradle; `release` signs with
apksigner using the `ANDROID_KEYSTORE_*` secrets and publishes a GitHub release.

Previewing in a sandbox without an emulator: `EXPO_OFFLINE=1 npx expo export --platform web`,
serve the output with an SPA fallback, screenshot with Playwright. Native widgets (tab bar,
icons, sheets, date picker) render differently or not at all on web; layout and colours are
representative.

## Bank SMS import

> **Currently switched off and not wired into the native app.** `SMS_IMPORT_ENABLED` in
> `src/lib/sms/config.ts` is `false`; no SMS permissions are declared, so the APK installs
> without Play Protect's sideloading block.
> Reason: Play Protect's enhanced fraud protection blocks sideloaded apps that request
> SMS/notification-listener/accessibility access. The plan is to ship through Google Play
> (internal testing first) with the "SMS-based money management" declaration. Re-enabling needs:
> (1) an Expo native module (local `modules/sms-capture`, via `npx create-expo-module --local`)
> ported from the Java in `plugins/sms-capture` with the same filter, queue and enable flag,
> (2) a JS bridge + sync hook replacing the deleted Capacitor `plugin.ts` / `use-sms-sync.ts`,
> (3) native Settings and Review screens (the web versions were removed in the Expo rewrite).
> The description below is the Capacitor design to port; the parser/ingest code is current.

- **Why a local plugin:** CI runs `npx cap add android` fresh each build and `android/` is
  gitignored, so native code can't live there. `plugins/sms-capture` is an npm package with
  `capacitor.android.src`; `cap sync` merges its manifest (RECEIVE_SMS, READ_SMS, receiver).
- **Flow:** `SmsReceiver` (system SMS broadcast) → `SmsFilter.isCandidate` (drops phone-number
  senders, OTPs, anything without an amount + debit word) → `SmsStore` queue in
  SharedPreferences (cap 300) → `smsReceived` event. In JS, `useSmsSync` (mounted in AppShell)
  drains the queue on launch, on foreground and on that event → `ingestSms` → `data.pending` →
  Home banner → `ReviewSheet` (pick category → `confirmPending` adds an Expense with
  `source: "sms"` and remembers merchant → category; or `dismissPending`).
- Settings → SMS Import toggled it (requests permission) and back-filled 30 days from the inbox.
- **Dedupe:** fingerprint = hash of the message body; `smsImport.seen` (cap 2000) stores
  fingerprints already added/dismissed.
- **Adding a bank format:** add a masked sample to `parser.test.ts`, then adjust patterns in
  `parser.ts`. The Java pre-filter must also accept it (`SmsFilter.java`).
- **Security invariants (from the Nov 2026 audit; keep them, they are tested):**
  - Secrets never reach storage. `SECRET` in `SmsFilter.java` (first layer, before the native
    queue) and in `parser.ts` (second layer) reject anything mentioning OTP, PIN, passcode,
    password, verification or auth code, CVV, or "do not share". Keep both regexes identical.
    Missing an expense is acceptable; storing an OTP is not.
  - Bodies over 2000 chars are rejected before any regex runs (concatenated SMS can reach ~39k).
  - Only `redactSmsBody` output is stored in `pending[].body` (4+ digit runs masked except the
    amount). Raw text exists only briefly in the native queue.
  - The native receiver captures only while `SmsStore` "enabled" is true; `useSmsSync` mirrors
    the in-app switch into it, and turning the switch off clears the queue.
  - Backup export (Settings → Data) blanks `pending[].body` and `sender`.
  - The receiver is protected by `BROADCAST_SMS`, so only the OS can deliver to it.
  - `app.json` sets `android.allowBackup: false`. Debug APKs are debuggable (adb `run-as`),
    so use the release APK for real data.
- **Play Store:** SMS permissions need the "SMS-based money management" declaration and are
  approved case by case. The Settings copy doubles as the prominent disclosure.
  A notification-listener source is the fallback if the declaration is refused.

## Domain rules (calc.ts / periods.ts)

- Periods: each ISO week has a `…-WD` block (Mon–Fri) and a `…-WE` block (Sat–Sun).
  Period ids look like `2026-W44-WD`.
- An entry's period comes from **its date** (`periodContains`), not from the stored
  `periodType`.
- Budgets are versioned by `effectiveFrom` and never retroactive. `budgetOn(date)` picks the
  latest one whose effectiveFrom ≤ date, and otherwise falls back to the earliest.
- Per-day planned amount = weekdayBudget/5 or weekendBudget/2. Monthly planned = the sum over
  the month's days, which handles blocks split across months.
- `monthProgress`: savings are only "banked" once a block has fully **closed** (it is past).
  Every month restarts at 0.
- Additions (extra money) raise a period's `remaining`. They are excluded from the month's
  `result` (planned − spent).
- Deleting a category leaves its expenses orphaned. The UI then shows "Other" or a blank
  category name.

## Design system (native)

Guided by Apple's HIG via the apple-design skill (https://github.com/dickwu/apple-design-skill).

- **Platform components first:** native tab bar, native form sheets, native date picker, native
  alerts (`Alert.alert`) for confirmations, SF Symbols / Material Symbols. Custom UI keeps
  platform sizing: touch targets of at least 44pt, list rows at least 56pt.
- **Colours** come only from `useTheme().colors` (`background`, `card`, `elevated`, `text`,
  `textMuted`, `hairline`, `accent`, `accentStrong`, `onAccent`, `under`, `over`). Themes: brass
  (default), carbon, violet, ocean (dark); blush, sand (light).
- **Type:** system font (SF Pro / Roboto) via `type.*` styles; money uses `tabular`. Cormorant
  Garamond italic (`type.display`) is the brand voice, for hero words only ("saved",
  "overspent", onboarding headlines).
- Tab screens use `Screen` (large title, scroll, bottom clearance for FloatingActions and the
  tab bar). Actions never live in the tab bar.
- Title case for buttons and sheet titles ("Add Expense", "Save Changes").
